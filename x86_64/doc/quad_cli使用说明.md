# Quad CLI 使用说明

## 1. 说明

`quad_cli` 是 Quad facade 层的命令行调试工具，按以下三个模块组织：

- 地图资源模块
- 定位模块
- 导航模块

本文面向 SDK 安装包用户。

以下命令默认在安装包解压后的 `x86_64/` 目录下执行，例如：

```bash
cd x86_64
```

## 2. 启动

直接运行：

```bash
./bin/quad_cli
```

常用参数：

```bash
./bin/quad_cli --help
./bin/quad_cli --log-level INFO
./bin/quad_cli --console-log-level DEBUG
./bin/quad_cli --file-log-level INFO
./bin/quad_cli --log-file ./quad_cli.log
```

当前 `quad_cli` 默认机器人 IP 为 `192.168.1.103`。

连接地址说明：

- `192.168.3.20`：适用于开发机通过 Wi-Fi 直接连接本体。
- `192.168.1.103`：适用于在上装内进行开发、由上装侧连接本体。

如果当前网络拓扑与默认值不一致，请在执行 `1. 连接机器人` 时手动输入实际 IP。

## 3. 菜单概览

### 连接

- `1` 连接机器人
- `2` 断开连接
- `3` 查看连接状态

### 地图资源模块

- `41` 刷新地图资源
- `42` 查看地图资源总览
- `43` 查看场景详情
- `44` 查看场景轨迹
- `45` 重命名路径
- `46` 导出子场景地图到本地
- `47` 监听地图资源事件

### 定位模块

- `51` 启动定位
- `52` 启动重定位
- `53` 停止定位
- `54` 查看定位状态
- `55` 监听定位状态

### 导航模块

- `61` 设置运动模式
- `62` 查看运动模式
- `63` 启动定点导航(Pose2D)
- `64` 启动循迹导航
- `65` 停止导航
- `66` 暂停导航
- `67` 恢复导航
- `68` 查看导航状态
- `69` 监听导航/暂停事件

## 4. 推荐操作流程

最常用的流程如下：

1. `1` 连接机器人
2. `41` 刷新地图资源
3. `42` / `43` / `44` 查看场景和轨迹
4. `51` 启动定位；若已知初始位姿，可用 `52` 启动重定位
5. `61` 设置运动模式为 `2=导航`
6. `63` / `64` 启动定点导航或循迹导航
7. 导航过程中可用 `66`、`67`、`65`
8. 用 `68` 查看最终导航状态

## 5. 常见命令说明

### 5.1 刷新地图资源

执行 `41` 后，CLI 会等待命令回调，并显示：

- 场景缓存是否有效
- 轨迹缓存是否有效
- 场景数
- 轨迹图数

如果后续要做定位或导航，建议先执行一次 `41`。

### 5.2 启动定位

执行 `51` 后，先选择场景，再等待定位命令结果。  
如果已知机器人初始位姿，可执行 `52` 启动重定位，依次输入场景、初始 `X`、初始 `Y` 和初始航向角。

重定位航向角单位为**度**，CLI 内部会用 `poseFromXYYawDegrees()` 构造初始位姿。

命令受理成功不等于定位缓存已经就绪；只有 `getLocalizationState().ready` 为 `true` 后，菜单顶部的 `已定位` 才会变成 `是`。  
可用 `54` 查看定位状态，也可用 `55` 监听定位状态事件。

循迹导航依赖定位状态。

### 5.3 设置运动模式

执行 `61`，建议切到：

- `0` 手动
- `1` 辅助
- `2` 导航

做导航前通常应设置为 `2`。

### 5.4 启动定点导航

执行 `63` 前需要先完成定位。典型输入顺序：

1. 选择或输入场景
2. 输入目标 `X`
3. 输入目标 `Y`
4. 输入目标航向角

目标航向角单位为**度**，不是弧度；如果输入类似 `1.57`，CLI 会提示该值表示 `1.57°`。

命令受理成功后，CLI 会继续打印导航事件，直到导航进入终态。输入 `q` 再回车只会退出本地等待，不会停止机器人侧导航任务。

### 5.5 启动循迹导航

执行 `64` 前需要先完成定位。典型输入顺序：

1. 选择轨迹图
2. 输入 `path_id`
3. 选择方向
4. 输入障碍等待超时秒数

命令受理成功后，CLI 会继续打印导航事件，直到：

- `已完成`
- `已取消`
- `失败`

如果输入 `q` 再回车，只会退出本地等待，导航任务仍可能继续在机器人侧执行。

### 5.6 监听事件

- `47` 监听地图资源事件
- `55` 监听定位状态事件
- `69` 监听导航/暂停事件

这些监控命令都用 `q` 回车退出。

## 6. 交互规则

- 大多数输入框中，直接回车表示取消当前操作
- 有默认值的输入框，直接回车表示使用默认值
- 大多数普通命令执行完后，CLI 会提示 `按 Enter 继续`
- 监控类命令和导航启动后的等待流程不会出现该提示，而是持续输出，直到你手动退出或导航进入终态

## 7. 常见问题

### 7.1 启动循迹导航失败，提示 `error=32`

实测常见表现为：

```text
error=32 (距离路线太远)
```

通常优先检查：

- 当前定位是否正确
- 选择的场景是否和当前定位场景一致
- 选择的路径是否正确
- 机器人当前位置是否离轨迹起点过远

### 7.2 为什么看到“输入 q 回车仅退出等待，导航会继续执行”

这是 CLI 的本地等待逻辑，不等于给机器人发送停止导航。  
如果要真正停止导航，请执行 `65`。

## 8. 示例

一个最小可用流程：

```text
1  -> 连接机器人
41 -> 刷新地图资源
51 -> 启动定位（或 52 启动重定位）
61 -> 设置运动模式为 2
64 -> 启动循迹导航
68 -> 查看导航状态
```
